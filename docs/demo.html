The problem: documents are opaque to AI

A PDF is a bag of glyphs at coordinates. Every AI pipeline pays to rebuild the structure the PDF threw away.
Layout is lost
Headings, tables, reading order — gone. Pipelines re-derive them with OCR, heuristics, and hope.
Tables smear
Cells collapse into a stream of tokens. Chunkers slice rows in half; retrieval returns garbage.
Not diffable
A one-word edit produces a totally different binary. git diff is useless; you re-index everything.
Vendor-locked
You need a parser per producer, per version. Structure lives in tooling, not in the file.
The shift: instead of AI struggling to understand humans' files, humans write in a format already built for AI reasoning.

08
On AWS

Drops straight into an AWS RAG stack

jdf chunk + jdf embed run offline and deterministic. Point the vectors at whatever store you run.

1
jdf convert
PDFs & LLM JSON → validated .jdf in your ingestion job (Lambda / Batch / Fargate).
2
jdf chunk
Section-aware, deterministic chunks → .chunks.jsonl. Same input → identical hashes.
3
jdf embed
Local Ollama or OpenAI today; per-element vectors. Feed Amazon Bedrock / Titan.
4
Store & serve
Push vectors to Amazon OpenSearch / Aurora pgvector; metadata is already first-class.
Determinism guarantee: same document + same options → byte-identical chunks & stable hashes. --incremental re-embeds only what changed.

09
Code

The whole ingestor is one loop — no PDF library

const doc = JSON.parse(fs.readFileSync('paper.jdf'));

for (const page of doc.pages)
  for (const el of page.elements) {
    const text = el.content ?? serialize(el);   // structure is already here
    await index.upsert({
      vector: await embed(text),
      metadata: { type: el.type, heading: el.heading,
                  page: page.number, title: doc.meta.title }
    });
  }
No pdfplumber. No OCR. No heading detection. The metadata you'd normally reconstruct is a field access.

Use case · AI workflows

LLMs emit JSON. Wrap it into a renderable, valid doc.

Models naturally produce JSON.

jdf convert accepts a full document, a bare element array, or a partial — wraps it into a schema-valid .jdf.

Output is always validated → the same step becomes a CI gate on model output. Renderable, diffable, grep-able — every time.

.github/workflows/docs.yml
- name: Validate model output
  run: |
    npx @uurtech/jdf-cli \
      convert dist/out.json \
      -o dist/out.jdf
    npx @uurtech/jdf-cli \
      validate dist/out.jdf
    # exits non-zero on bad schema
Structured output that can't be malformed: the JDF schema is a guaranteed-valid generation target for OpenAI response_format, Anthropic tools, Bedrock.

The CLI

Five verbs. Install with npx, npm, or Homebrew.

$ jdf validate doc.jdf                          schema-check any document (CI gate)
$ jdf convert paper.pdf -o paper.jdf --json     PDF → JDF, single JSON file
$ jdf convert response.json -o out.jdf          LLM / agent JSON → validated JDF
$ jdf convert notes.md -o notes.jdf             Markdown → JDF
$ jdf chunk paper.jdf                           → paper.chunks.jsonl (deterministic)
$ jdf embed paper.jdf --incremental             → paper.embeddings.json (ollama/openai)
